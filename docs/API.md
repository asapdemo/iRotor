# iRotor — опис інтерфейсів (API)

Документ для інтеграції зовнішніх програм з платою iRotor.
Відповідає прошивці **iRotor v1.3.x** (азимутальні команди `az`, `preset`, `/az/goto` і поле `err` з’явились у v1.1.0, команда `zero` — у v1.2.0,
збереження швидкості `save` і пам’ять позиції серво — у v1.3.0),
формат налаштувань **v13**. Версію конкретної плати видно в `GET /az/config` (поле `fw`)
або в UART-команді `version`.

---

## 1. Огляд

Плата iRotor (STM32F103 + Ethernet W5500) керує двома сервоприводами. Один з них — привод поворотного механізму (азимут).

| Інтерфейс | Транспорт | Порт | Для чого |
|---|---|---|---|
| **JSON API** | UDP (за замовчуванням) або TCP | 6700 | Керування з програм: швидкий, короткі повідомлення, без пароля |
| **HTTP API** | HTTP/1.1 | 80 | Вебінтерфейс плати, налаштування, азимут, оновлення прошивки |
| **UART-консоль** | 115200 8N1 | — | Сервіс і аварійне відновлення |

Мережа за замовчуванням: **192.168.67.121**, маска 255.255.255.0, шлюз 192.168.67.1, DHCP вимкнено.
Налаштування, збережені на платі, мають пріоритет над заводськими й переживають оновлення прошивки.

**Що обрати для інтеграції.** Поворот на азимут, виклик пресета, швидкість і опитування стану — **JSON API по UDP**:
плата сама перераховує азимут в імпульс і відхиляє недосяжні кути. HTTP API потрібен для налаштування механіки,
прив’язки до азимута, редагування пресетів, мережі й оновлення прошивки.

## 2. Швидкий старт

Стан плати по HTTP:
```sh
curl http://192.168.67.121/data
```

Повернути серво 1 на 1500 мкс зі швидкістю 100 через JSON API (Python):
```python
import json, socket

BOARD = ("192.168.67.121", 6700)
sock = socket.socket(socket.AF_INET, socket.SOCK_DGRAM)
sock.settimeout(0.5)

def api(request: dict) -> dict:
    """Надсилає запит і повертає поточний стан плати (див. розділ 6.1)."""
    sock.sendto(json.dumps(request, separators=(",", ":")).encode(), BOARD)
    return json.loads(sock.recv(1024))

# Повернути механізм на азимут 200,0° зі швидкістю 100 (кути — у десятих градуса)
state = api({"servo1_speed": 100, "az": 2000})
if "err" in state:
    raise RuntimeError(state["err"])          # напр. "unreachable" — 200° у недосяжній зоні

# Дочекатися зупинки
while state["az"]["pos"] != state["az"]["target"]:
    state = api({})
print("стоїть на", state["az"]["pos"] / 10, "°")
```

## 3. Модель серво

Кожне серво (`servo1`, `servo2`) має такі величини:

| Величина | Одиниці | Діапазон | Значення |
|---|---|---|---|
| **ціль** (`servoN`) | мкс ширини імпульсу | 0…3000 | Куди серво має прийти. **0 — вихід вимкнено** (імпульсів немає, серво не тримає позицію) |
| **позиція** (`servoN_pos`) | мкс | 0…3000 | Імпульс, який плата видає зараз. Під час плавного руху відстає від цілі |
| **швидкість** (`servoN_speed`) | — | 0…255 | Як швидко позиція наздоганяє ціль (див. нижче) |
| **центр** (`servoN_center`) | мкс | 1…3000 | Збережена у flash «центральна» позиція (за замовчуванням 1372) |

Сигнал: 50 Гц, імпульс задається з кроком 1 мкс. Позиція оновлюється кожні 20 мс.

**Швидкість:**
- `0` — тримати поточну позицію (рух зупиняється там, де є; ціль не змінюється);
- `1…254` — плавний рух: ≈3,9 мкс/с на одиницю швидкості (1 → ~4 мкс/с, 128 → ~500 мкс/с, 254 → ~990 мкс/с);
- `255` — миттєво (позиція одразу дорівнює цілі; фактична швидкість обмежена самим серво).

Після ввімкнення плати діє **стартова швидкість** з flash (`pwm_defaults.servoN_speed`, розділ 6.3). Звичайна команда
швидкості змінює її лише до перезавантаження; щоб зберегти, додайте `save` (JSON API `"save":1`, HTTP `&save=1`).
Повзунок швидкості у вебінтерфейсі зберігає завжди.

Особливі випадки: вимкнення виходу (у 0) миттєве. Зміна швидкості на 255 під час руху одразу ставить позицію в ціль.

**Остання позиція переживає перезавантаження.** Серво не має зворотного зв’язку, тому плата записує у flash, де серво
зупинилось (через ~1 с після зупинки, а під час довгого руху — раз на 10 с). Після старту, при ввімкненні виходу
(стартова позиція або перша команда), серво плавно їде **від збереженої позиції** з поточною швидкістю, а не стрибає
на повній швидкості. Миттєво вихід вмикається лише при швидкості 255 або якщо позиція ще ніколи не зберігалась.
Якщо механізм рухали руками при вимкненій платі або живлення зникло посеред руху, перший рух піде від збереженої позиції.

**Рух завершено**, коли `servoN_pos == servoN`.
**Зупинити рух на місці:** записати ціль, що дорівнює поточній позиції (`servoN = servoN_pos`), швидкість не чіпати.

**Безпечний діапазон механізму.** Плата приймає 0…3000 мкс, але поворотний механізм фізично ходить лише в межах
`pmin…pmax` з `/az/config` (зараз 801…2012 мкс). За межами — упор. Контролюйте діапазон на своєму боці.

## 4. Азимут

**Азимут рахує плата.** Кути в API — цілі числа в **десятих частках градуса** (`az`: 0…3599 = 0,0°…359,9°),
0 = північ, за годинниковою стрілкою.

| Що | Як |
|---|---|
| Повернути на азимут | JSON API `{"az": 2000}` або `GET /az/goto?az=2000` |
| Поїхати на пресет | JSON API `{"preset": 2}` або `GET /az/goto?preset=2` |
| Нуль (1346 мкс) | JSON API `{"zero": 1}` або `GET /az/goto?zero=1`; працює і без прив’язки |
| Поточний і цільовий азимут | блок `az` у стані: `"az":{"pos":1987,"target":2000}` (JSON API, `GET /data`) |
| Чи рух завершено | `az.pos == az.target` |
| Зупинити на місці | записати ціль = поточна позиція серво (розділ 3) |

Плата відхиляє команду (поле `err`, розділ 5.2), якщо механізм ще не прив’язаний до азимута (`not_calibrated`)
або кут лежить у недосяжній зоні (`unreachable`). Серво їде з поточною швидкістю (`servoN_speed`).
`az.pos` / `az.target` дорівнюють `null`, коли азимут невідомий: прив’язки немає або вихід серво вимкнено.

**Точність.** Імпульс задається з кроком 1 мкс ≈ 0,22° (263° на 1211 мкс), тому фактичний азимут може відрізнятися
від заданого на ±0,1…0,2° (наприклад, команда 90,0° → `az.pos` 90,1°).

**Прив’язка** (один раз після монтажу або зміни механіки): підвести механізм до відомого орієнтира (JSON API
`servoN` або кнопки вебінтерфейсу), дочекатися зупинки, `GET /az/cal?az=<азимут орієнтира ×10>` (розділ 7.4).

### 4.1 Модель (для довідки)

Плата використовує лінійну модель. Знати її потрібно лише для власних розрахунків, наприклад щоб
заздалегідь показати користувачу недосяжну зону. Параметри з `/az/config` (кути — у десятих градуса):

| Поле | Значення |
|---|---|
| `servo` | Яке серво є приводом азимута (1 або 2) |
| `pmin`, `pmax` | Імпульси крайніх положень, мкс |
| `range` | Кут повороту між `pmin` і `pmax`, ×0,1° (2630 = 263,0°) |
| `inv` | 0 — більший імпульс крутить за годинниковою стрілкою, 1 — проти |
| `cal` | `[pulse, azimuth×10]` — прив’язка: цей імпульс відповідає цьому азимуту; `null` — не прив’язано |

Формули (лінійна модель):
```python
def make_geometry(cfg):
    k = (cfg["range"] / 10) / (cfg["pmax"] - cfg["pmin"])   # градусів на 1 мкс
    d = -1 if cfg["inv"] else 1
    cal_pulse, cal_az10 = cfg["cal"]                        # перевірте, що cfg["cal"] не None

    def azimuth(pulse):                                     # імпульс -> азимут
        return (cal_az10 / 10 + d * (pulse - cal_pulse) * k) % 360

    def pulse_for(az):                                      # азимут -> імпульс, None = недосяжно
        offset = (d * (az - azimuth(cfg["pmin"]))) % 360
        if offset > 360 - 1e-6:
            offset = 0.0
        if offset > cfg["range"] / 10 + 1e-6:
            return None                                     # азимут у «мертвій» зоні
        return min(cfg["pmax"], max(cfg["pmin"], round(cfg["pmin"] + offset / k)))

    return azimuth, pulse_for
```
Досяжний сектор: від `azimuth(pmin)` (або `azimuth(pmax)`, якщо `inv = 1`) за годинниковою стрілкою на `range/10` градусів.
Решта кола — недосяжна зона. Плата рахує те саме цілими числами; результати збігаються з цими формулами
до 1 мкс / 0,05°, а на самій межі сектора можуть відрізнятися на пів кроку.

## 5. JSON API (порт 6700)

Режим (UDP або TCP), порт і ввімкнення задаються в налаштуваннях мережі (розділ 7.6). Зміни застосовуються одразу,
без перезавантаження. **Пароля немає**, навіть якщо пароль увімкнено для вебінтерфейсу.

### 5.1 Запит

Один JSON-об’єкт, **не більше 191 байта**. Усі поля необов’язкові; передавайте лише ті, що треба змінити.

| Поле | Тип | Діапазон | Дія |
|---|---|---|---|
| `servo1`, `servo2` | ціле | 0…3000 | Нова ціль, мкс (0 — вимкнути вихід) |
| `servo1_speed`, `servo2_speed` | ціле | 0…255 | Швидкість (розділ 3) |
| `save` | ціле | 1 | Зберегти швидкості з цього ж запиту у flash як стартові (діють після перезавантаження) |
| `servo1_center`, `servo2_center` | ціле | 0…3000 | Зберегти центр у flash. **0 — взяти поточну позицію серво** |
| `az` | ціле | 0…3599 | Повернути механізм на азимут (×0,1°), розділ 4 |
| `preset` | ціле | 0…7 | Повернути на азимут збереженого пресета |
| `zero` | ціле | 1 | Поставити серво азимута в нуль — 1346 мкс (`zero` у `/az/config`). Прив’язка не потрібна |

Порядок застосування всередині одного запиту: центри → швидкості → цілі `servoN` → `az` (або `preset`, якщо `az` немає; або `zero`, якщо немає жодного з них).
Тому `{"az":2000,"servo1_speed":10}` одразу поїде вже з новою швидкістю. Якщо в одному запиті є і `servoN`, і `az`
для того самого серво, перемагає `az`.

Порожній запит `{}` (або будь-який) — просто запит стану.

Правила розбору:
- значення — лише цілі десяткові числа (`1500`; рядок `"1500"` теж приймається); дробові (`1500.5`) і від’ємні — помилка;
- ключ має йти після `{` або `,`;
- **на першому некоректному значенні обробка зупиняється**: поля, оброблені раніше, уже застосовані, решта — ні.
  У відповіді з’являється `"err":"bad_value"`.

### 5.2 Відповідь

На кожен запит плата відповідає поточним станом — той самий JSON, що `GET /data` (розділ 6.1).
Стан знімається **після** застосування запиту.

Якщо запит не виконано, на початку відповіді є поле `err`:
```json
{"err":"unreachable","uptime_s":1234,"pwm":{...},"az":{"pos":1987,"target":1987}}
```
| `err` | Причина |
|---|---|
| `bad_value` | Значення поза діапазоном або не ціле число |
| `not_calibrated` | `az`/`preset`, а механізм ще не прив’язаний до азимута (`/az/cal`) |
| `unreachable` | Азимут у недосяжній зоні механізму (для `zero`: 1346 мкс поза `pmin…pmax`) |
| `no_preset` | Слот пресета порожній |
| `save_failed` | Не вдалося записати у flash (`servoN_center`, `save`) |

Немає `err` — усе з запиту застосовано.

### 5.3 UDP

- Відповідь надходить на адресу й порт відправника.
- Опитувати стан можна часто (10–20 разів на секунду — без проблем).
- Втрата пакета можлива: робіть тайм-аут (300–500 мс) і повтор. Повтор команди безпечний — команди ідемпотентні
  (крім `servoN_center`, який щоразу пише у flash; `save` пише у flash лише якщо швидкість змінилась).

### 5.4 TCP

- Плата слухає порт; одночасно обслуговується **один** клієнт. **Нове з’єднання закриває попереднє.**
- Одне `send` = один JSON-запит. Роздільників повідомлень немає: надсилайте наступний запит лише після отримання відповіді.
- З’єднання без запитів понад **30 с** закривається платою.

## 6. Формати даних

### 6.1 Стан (`GET /data`, відповідь JSON API)

```json
{"uptime_s":1234,"pwm":{"servo1":1785,"servo2":0,"servo1_speed":40,"servo2_speed":255,
 "servo1_pos":1702,"servo2_pos":0,"servo1_center":1372,"servo2_center":1372},
 "az":{"pos":1823,"target":2000}}
```
| Поле | Значення |
|---|---|
| `err` | Лише у відповіді JSON API, якщо запит не виконано (розділ 5.2) |
| `uptime_s` | Секунд від старту плати (скидається при перезавантаженні — зручно, щоб помітити ребут) |
| `pwm.servoN` | Ціль, мкс |
| `pwm.servoN_pos` | Поточна позиція, мкс |
| `pwm.servoN_speed` | Швидкість 0…255 |
| `pwm.servoN_center` | Збережений центр, мкс |
| `az.pos` | Поточний азимут серво азимута, ×0,1°; `null` — невідомий (немає прив’язки або вихід вимкнено) |
| `az.target` | Цільовий азимут, ×0,1°; `null` — невідомий |

### 6.2 Конфіг азимута (`GET /az/config`)

```json
{"fw":{"v":"1.0.1","git":"v1.0.1","build":"2026-11-19 12:30","settings":13},
 "servo":1,"pmin":801,"pmax":2012,"range":2630,"inv":0,"zero":1346,"cal":[1418,1470],
 "presets":[[0,230,"Північний схід"],[2,1800,"Південь"]]}
```
| Поле | Значення |
|---|---|
| `fw.v` | Версія прошивки (SemVer) |
| `fw.git` | `git describe` збірки; релізна збірка — рівно `vX.Y.Z` |
| `fw.build` | Час збірки |
| `fw.settings` | Версія формату налаштувань |
| `servo`, `pmin`, `pmax`, `range`, `inv`, `cal` | Механіка й прив’язка (розділ 4) |
| `zero` | Імпульс нульової позиції, мкс (команда `zero`); з’явилось у v1.2.0 |
| `presets` | Непорожні слоти: `[слот 0…7, азимут×10, "назва"]` |

### 6.3 Налаштування (`GET /board/data`, `GET /net_settings/data` — однаковий JSON)

```json
{"dhcp":0,"dhcp_fallback_attempts":3,
 "pwm_defaults":{"servo1":1372,"servo2":0,"servo1_speed":255,"servo2_speed":255,"servo1_center":1372,"servo2_center":1372},
 "json_api":{"enabled":1,"mode":0,"port":6700},
 "web_auth":{"enabled":0,"password":"admin"},
 "ip":"192.168.67.121","mask":"255.255.255.0","gateway":"192.168.67.1","dns":"8.8.8.8","mac":"02:12:34:56:78:9A"}
```
`pwm_defaults.servoN` / `servoN_speed` — стартова позиція і швидкість після ввімкнення. `json_api.mode`: 0 — UDP, 1 — TCP.
**Увага:** пароль вебінтерфейсу віддається відкритим текстом.

## 7. HTTP API (порт 80)

### 7.1 Загальні правила

- **Авторизація:** якщо в налаштуваннях увімкнено `web_auth`, кожен запит потребує HTTP Basic.
  Ім’я користувача будь-яке, перевіряється лише пароль. Без пароля — `401 Unauthorized` з `WWW-Authenticate: Basic`.
- **Одне з’єднання за раз.** Вебсервер обробляє запити строго по черзі; поки обробляється один, інші з’єднання
  відхиляються. Надсилайте запити послідовно, при помилці з’єднання повторіть через 100–200 мс.
  З’єднання, яке за 3 с не надіслало повний запит, закривається.
- Кожна відповідь закриває з’єднання (`Connection: close`). Заголовки запиту — до ~1,5 КБ.
- Зміни стану й налаштувань — **GET із параметрами в рядку запиту** (історично). Значення в URL кодуються як звичайно
  (`%20` або `+` для пробілу, UTF-8 для кирилиці).
- Відповідь на команду: `200 {"ok":1}` або `400 {"ok":0}` (без пояснення причини; виняток — `/az/goto`, див. 7.4).
  Невідомий шлях — `404 not found`.
- Опитування `/data` — не частіше 4 разів на секунду; для частішого опитування використовуйте JSON API.

### 7.2 Перелік

| Метод і шлях | Призначення |
|---|---|
| `GET /` | Вебінтерфейс (HTML, `Content-Encoding: gzip`) |
| `GET /data` | Стан (6.1). Синонім: `GET /uptime` |
| `GET /pwm?ch=…&v=…` | Керування серво (7.3) |
| `GET /az/goto?az=…` / `?preset=…` / `?zero=1` | Повернути на азимут / пресет / в нуль (7.4) |
| `GET /az/config` | Конфіг азимута, пресети, версія прошивки (6.2) |
| `GET /az/set?…` | Механіка (7.4) |
| `GET /az/cal?…` | Прив’язка до азимута (7.4) |
| `GET /az/preset?…` | Пресети (7.4) |
| `GET /board/data` | Налаштування (6.3) |
| `GET /board/set?…` | Стартова позиція і швидкість (7.5) |
| `GET /net_settings/data` | Налаштування (6.3) |
| `GET /net_settings/set?…` | Мережа, JSON API, пароль (7.6) |
| `GET /reboot` | Перезавантаження: `{"reboot":1}`, через ~50 мс ребут |
| `POST /fwupdate/start` | Перехід у режим оновлення прошивки (розділ 8) |
| `GET /net_settings`, `GET /fwupdate` | `302` на відповідні вкладки вебінтерфейсу |

### 7.3 `GET /pwm?ch=<канал>&v=<значення>`

| `ch` | `v` | Дія |
|---|---|---|
| `servo1`, `servo2` | 0…3000 | Ціль, мкс |
| `servo1_speed`, `servo2_speed` | 0…255 | Швидкість; з `&save=1` — ще й зберегти у flash як стартову |
| `servo1_center`, `servo2_center` | 1…3000 або без `v` | Зберегти центр у flash; без `v` — поточна позиція серво |

### 7.4 Азимут

**`GET /az/goto?az=<азимут×10>`**, **`GET /az/goto?preset=<0…7>`** або **`GET /az/goto?zero=1`** — повернути механізм
(те саме, що `az`/`preset`/`zero` у JSON API). `zero=1` ставить серво азимута на 1346 мкс і працює без прив’язки. Нічого не зберігає у flash.
Відповідь: `200 {"ok":1,"pulse":1662}` (імпульс, у який поїде серво) або `400 {"ok":0,"err":"unreachable"}`
(коди `err` — розділ 5.2).

Команди нижче одразу зберігають зміни у flash.

**`GET /az/set?pmin=&pmax=&range=&inv=&servo=`** — механіка; усі параметри обов’язкові.
`1 ≤ pmin < pmax ≤ 3000`, `range` = кут×10 (1…3600), `inv` 0/1, `servo` 1/2.
Зміна `servo` скидає прив’язку.

**`GET /az/cal?az=<азимут×10>`** — прив’язати **поточну позицію** серво азимута до азимута (0…3599).
Плата відмовить (`400`), якщо серво ще рухається (`pos ≠ ціль`) або позиція поза `pmin…pmax`.
`GET /az/cal?clear=1` — скинути прив’язку.

**`GET /az/preset?slot=<0…7>&az=<азимут×10>&name=<назва>`** — записати пресет у слот (перезаписує).
Назва — до 31 байта UTF-8 (≈15 кириличних літер), без `"`, `\` і керівних символів.
`GET /az/preset?slot=<0…7>&del=1` — очистити слот.
При збереженні плата не перевіряє, чи досяжний азимут пресета; виклик такого пресета поверне `unreachable`.

### 7.5 `GET /board/set?servo1=&servo2=[&servo1_speed=&servo2_speed=]`

Стартові позиції (обидві обов’язкові, 0…3000) і швидкості (необов’язкові, 0…255).
**Застосовується одразу** (обидва серво їдуть у ці позиції) і зберігається у flash.

### 7.6 `GET /net_settings/set?…`

Усі параметри обов’язкові, крім `dhcp`:

| Параметр | Значення |
|---|---|
| `dhcp` | `0` — статична адреса, інше — DHCP; якщо параметра немає — не змінюється |
| `dhcp_fallback_attempts` | 0…255 спроб DHCP до переходу на статичну (0 — без кінця) |
| `ip`, `mask`, `gateway`, `dns` | `A.B.C.D` |
| `mac` | `XX:XX:XX:XX:XX:XX` (або через `-`), не груповий, не нулі/FF |
| `json_api_enabled` | 0/1 |
| `json_api_mode` | 0 — UDP, 1 — TCP |
| `json_api_port` | 1…65535 |
| `web_auth_enabled` | 0/1 |
| `web_password` | 1…31 друкованих ASCII-символів без пробілів, `"` і `\` |

Зберігається у flash одразу. JSON API і пароль діють одразу; **адреса й DHCP — після перезавантаження** (`/reboot`).

## 8. Оновлення прошивки

> ⚠ Під час оновлення плата нічим не керує. Обірване оновлення (живлення, мережа, закритий клієнт) залишає плату
> з частково записаною прошивкою — відновлення лише програматором ST-Link. Повторюйте невдалі блоки, не обривайте процес.

1. **`POST /fwupdate/start`** (з авторизацією, якщо ввімкнена) → `{"ram_server":1}`.
   Плата переходить у режим оновлення: звичайні HTTP і JSON API недоступні, далі працюють лише два маршрути без авторизації.
   Зачекайте ~500 мс.
2. **`POST /chunk?off=<зміщення>&len=<довжина>&crc=0x<crc32>`**, тіло — сирі байти (`application/octet-stream`).
   - `off` — кратне 1024 (сторінка flash), від 0; `len` — до 1024 і кратне 4;
   - образ доповніть байтами `0xFF` до довжини, кратної 4; максимальний розмір — 62 464 байти (61 КБ; з v1.3.0, раніше 63 КБ);
   - кожен блок стирає свою сторінку і записується; плата перевіряє CRC записаного;
   - відповідь `{"ok":1}` або `400 {"ok":0}` — тоді повторіть той самий блок (вебінтерфейс робить до 4 спроб);
   - надсилайте блоки послідовно від 0.
3. **`POST /finish`** → `{"done":1}`, плата перезавантажується в нову прошивку (~0,5 с).
   Останні 3 КБ flash (журнал позицій серво і сторінка налаштувань) не стираються.

CRC — апаратний CRC32 STM32: поліном `0x04C11DB7`, початкове значення `0xFFFFFFFF`, без віддзеркалення і фінального XOR,
обчислюється по 32-бітних словах little-endian:
```python
def stm32_crc(data: bytes) -> int:
    crc = 0xFFFFFFFF
    for i in range(0, len(data), 4):
        crc ^= int.from_bytes(data[i:i + 4], "little")
        for _ in range(32):
            crc = ((crc << 1) ^ 0x04C11DB7) & 0xFFFFFFFF if crc & 0x80000000 else (crc << 1) & 0xFFFFFFFF
    return crc
```

### 8.1 Мітка версії в образі

Кожен образ iRotor містить 80-байтну мітку, за якою можна перевірити файл **до** запису. Шукайте сигнатуру
`AZFWINF1` на зміщеннях, кратних 4:

| Зміщення | Розмір | Поле |
|---|---|---|
| 0 | 8 | Сигнатура `AZFWINF1` (без нуля в кінці) |
| 8 | 4 | Ідентифікатор плати, байти `SAZ1` |
| 12 | 2 | Версія major (uint16 LE) |
| 14 | 2 | minor |
| 16 | 2 | patch |
| 18 | 2 | Версія формату налаштувань |
| 20 | 40 | `git describe`, рядок із нулем |
| 60 | 20 | Час збірки `YYYY-MM-DD HH:MM`, рядок із нулем |

Рекомендації: не прошивати, якщо ідентифікатор не `SAZ1`; попереджати, якщо версія налаштувань у файлі менша, ніж на
платі (`fw.settings`), — тоді всі налаштування скинуться до заводських.
Релізні файли: `iRotor-vX.Y.Z.bin` у релізах репозиторію разом із `SHA256SUMS`.

## 9. UART-консоль

115200 бод, 8N1, команди завершуються `\r` або `\n`.

| Команда | Дія |
|---|---|
| `help` | Список команд |
| `version` | `fw=1.0.1 git=v1.0.1 build=… settings=13` |
| `ping` | `pong` |
| `get_settings` | Налаштування в RAM |
| `set_dhcp 0/1`, `set_ip A.B.C.D`, `set_mask …`, `set_gw …`, `set_dns …`, `set_mac XX:…` | Мережа (лише в RAM) |
| `set_auth 0/1`, `set_password PASSWORD` | Пароль вебінтерфейсу (в RAM) |
| `save` / `load` | Записати налаштування у flash / прочитати з flash |
| `ip_info`, `wstatus`, `w_dhcp`, `clock_info` | Діагностика мережі й тактування |
| `reboot` | Перезавантаження |

`set_*` змінюють лише RAM — для збереження виконайте `save`.
**Аварійний доступ:** при старті плата посимвольно надсилає `[Starting]
` і чекає кожен символ назад протягом 10 мс
(перемичка TX–RX або програма, що миттєво повертає отримане). Якщо всі символи повернулись, плата до наступного
перезавантаження вмикає DHCP і вимикає пароль вебінтерфейсу (налаштування у flash не змінюються).

## 10. Обмеження і рекомендації

- **Безпека.** JSON API не має авторизації; HTTP — лише Basic без шифрування; команди — GET-запити. Тримайте плату
  в ізольованій мережі.
- **Ресурс flash.** Збереження центру, пресетів, налаштувань, прив’язки, швидкості з `save` перезаписують сторінку flash
  (~10 000 циклів). Не викликайте їх у циклі; для частої зміни швидкості надсилайте її без `save`.
- **Нестабільний зв’язок.** HTTP: повторюйте запит при помилці з’єднання. UDP: тайм-аут і повтор.
- **Перезавантаження плати** видно за зменшенням `uptime_s`. Після старту серво їдуть у стартові позиції (7.5).
- **Сумісність.** Нові поля в JSON можуть з’являтися в наступних версіях — ігноруйте невідомі. Несумісні зміни API —
  лише зі збільшенням major-версії прошивки (`fw.v`).
